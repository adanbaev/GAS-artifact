## Post-benchmark secret-handling hardening

The raw benchmark CSV files were recorded on 21-23 August 2026. The public
`SecurityUtil.java` and `SecuritySecretsConfig.java` were subsequently hardened
to reject absent, blank, or documented placeholder values and to require
separately supplied signature and integrity-chain secrets. This post-run change
does not alter the benchmark modes, measured database operations, protected
23-field representation, HMAC-SHA-256 algorithm, or evidence-persistence
semantics represented by the recorded CSV files. Running the matching full
application with the current sources requires both `SECURITY_SIGNATURE_SECRET`
and `INTEGRITY_CHAIN_SECRET` to be supplied explicitly.

The manuscript and its bibliography are not included or modified by this
packaging step.
